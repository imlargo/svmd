# The mdsvex audit

Every issue currently open on [pngwn/MDsveX](https://github.com/pngwn/MDsveX/issues), read against svmd’s actual source, tests, and documented decisions — and where a claim was checkable in minutes, checked for real rather than assumed. Two things changed in svmd because of this pass: an ambient `*.md` type export it didn’t have this morning, and a verified fix to how third-party remark plugins compose with its grammar.

Generated from a live `gh issue list --repo pngwn/MDsveX --state open` pull of all 163 open issues. Verdicts are this session’s own analysis against svmd’s source, test suite and documented design decisions (ARCHITECTURE.md, SPEC.md, GRAMMAR.md) — two are backed by a real compile run against the current build, not inference.

## Shipped and verified today

**`@svmd/vite/client`** — mdsvex has never shipped ambient `*.md` types ([#286](https://github.com/pngwn/MDsveX/issues/286), [#669](https://github.com/pngwn/MDsveX/issues/669)) — and neither had svmd, until this pass. Every project so far (svmd’s own example, coral) had hand-rolled the same `declare module '*.md'`. It now ships from the package itself: one `/// <reference types="@svmd/vite/client" />` line, verified against a real `svelte-check`.

**Plugin interop** — mdsvex has several reports of third-party remark plugins silently not working ([#533](https://github.com/pngwn/MDsveX/issues/533) remark-directive, [#665](https://github.com/pngwn/MDsveX/issues/665) remark-github-alerts, [#737](https://github.com/pngwn/MDsveX/issues/737)). Compiled `remark-directive` against a real svmd build just now: it correctly registers its micromark extension through unified’s own data channel and renders `:::name` containers — not assumed, run.
